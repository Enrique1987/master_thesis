# 1. Introduction

This Master's Thesis is approached mainly from the perspective of a data engineer: the person responsible for creating systems and infrastructure that make data available wherever it is required. The project focuses especially on monitoring a Big Data infrastructure.

## 1.1 Problem statement

### Data pipeline

The business idea behind the project is a small company that wants to make stock-market investments based on opinions published by the specialist financial press.

Financial newspapers and blogs publish daily articles about the prospects of companies and markets. Some companies receive positive coverage and later collapse in value, while others perform better than expected. With so many articles and authors, it is difficult for a reader to know whose opinion is reliable. One possible method is to follow each author over time and compare their predictions with subsequent market behavior.

The platform therefore needs to collect economic articles and retain, at minimum, the author, publication date, topics, and full text. This information can later feed data-science processes such as entity extraction and sentiment analysis.

### Monitoring

A Big Data platform must not be treated as a black box. The organization needs to know what happens inside the infrastructure and to analyze the logs produced by its services.

The example company offers web-based investment services. Its servers generate access logs for legitimate users, automated agents, and potential attackers. Monitoring must therefore cover application activity, infrastructure health, network traffic, security events, and the data generated by the pipeline itself.

## 1.2 Project objectives

The project aims to build an end-to-end Big Data architecture and examine the technologies required at each stage:

1. Collect economic-news content with a web crawler.
2. Store the extracted records as JSON documents.
3. Introduce Apache Kafka to decouple producers and consumers and handle larger event volumes.
4. Use MongoDB as the primary distributed document database.
5. Use Elasticsearch as a secondary store optimized for search and log analysis.
6. Collect logs and metrics with the Elastic Beats family.
7. Transform and enrich events with Logstash.
8. Explore and visualize indexed data with Kibana.
9. Study Machine Learning capabilities for identifying anomalies.
10. Define future extensions for cloud deployment, orchestration, streaming, and NLP.

## 1.3 Work plan and technical description

The work follows the data lifecycle. Each technology is first introduced conceptually and then applied to the project. The chapters remain open to future improvement in keeping with a continuous-development philosophy.

The proof of concept was assembled on a local computer with several virtual machines, simulating an on-premises Big Data infrastructure. The main technologies are Python and Scrapy for collection, Java and Apache Kafka for event distribution, MongoDB and Elasticsearch for storage, and the Elastic Stack for observability and visualization.
